## Backups and independent restores

[Preparation run 41207070887](https://github.com/sebaram/multi_display_artworks/actions/runs/41207070887) passed. Under `v2-rc1-20261031c`, application writes were stopped, MongoDB and media were backed up at the same point, then the legacy app was restarted. The candidate and legacy images each ran against independent DB/media copies. No test accounts were added to the original accounts or production database.

Staging uses internal Docker bridges only, with no host/public port publication. The checker reads HTTP/media through the server's internal container IPs; temporary-administrator and Socket.IO checks run inside the isolated candidate. Only the production cutover candidate uses the existing production network and loopback 51739.

Backups, secret environment configuration, original DB records and detailed check evidence are not uploaded as CI artifacts or committed to Git. Failed-attempt data copies are preserved too; only temporary containers/networks are shut down after checking ownership, isolation and image identity.

[Copy acceptance 41208453549](https://github.com/sebaram/multi_display_artworks/actions/runs/41208453549) passed. The legacy image was run against the candidate-written copy to check gallery/media recovery; after returning to the candidate, persistence and temporary-data cleanup were also checked. Tag `v2.0.0-rc.1` was preserved at the validated product source.

Check samples use the same `_cls` conditions as the legacy MongoEngine implementation. The first original image record returned by an unfiltered query also returned 404 under legacy Flask; it was not modified or deleted. For same-origin absolute URLs stored in actual media, only the path was extracted to compare bytes in the isolated copies. Successful copy checks do not establish current availability of external media services.

[Failed temporary-stack shutdown](https://github.com/sebaram/multi_display_artworks/actions/runs/41207714332) and [completed RC-stack shutdown](https://github.com/sebaram/multi_display_artworks/actions/runs/41208597535) also passed. The fix follows the stored lists/order in `Room.walls` and `Wall.images/splats/gltfs/webpages`, as the legacy implementation did. Explicit moves/deletions, AI layout and editor context use the same membership. Boundary checks for ordinary metadata editing use the wall actually displaying the artwork, and the editor retains that context. Displayed artwork ID/order checks were added to production-copy acceptance and public smoke checks.

## Cutover gates

1. Compare original IDs, reference order, account hashes, indexes and media in a copy. Check temporary administrator login, preset/upload/apply/restart persistence and two visitors' reactions/playback state.
2. Rerun the legacy image against the candidate-written copy to verify gallery/media recovery, then return to the candidate.
3. Merge the PR finalizing the `2.0.0` version and documentation into `master` with a normal merge commit. After push CI passes for the final master SHA, prepare a new image from that same SHA and repeat copy acceptance.
4. After the final paired backup, check the candidate privately on 51739. Add the 44 default presets through an import that does not overwrite existing entries. Promote only the same image to public port 51736.
5. After verifying public HTTPS, permanent room/wall URLs and Socket.IO, record tag `v2.0.0` and a GitHub Release at the actual deployed commit. On failure, recover with the legacy image/configuration captured for this cutover.

## Explicit remaining verification scope

Actual Quest 3 VR/controller/hand checks, physical microphone/camera/external-network TURN checks and comprehensive phone resource/thermal measurements were not performed. YouTube external-provider blocking is not treated as successful playback. Private FLAME/GaussianAvatars assets are excluded from the production image and service.
