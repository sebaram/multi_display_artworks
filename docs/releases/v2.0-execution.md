## 백업과 독립 복원

[준비 실행 41207070887](https://github.com/sebaram/multi_display_artworks/actions/runs/41207070887)이 성공했다. `v2-rc1-20261031c`에서 앱 쓰기를 멈추고 MongoDB와 미디어를 같은 시점으로 백업한 뒤 기존 앱을 재시작했다. 두 독립 DB·미디어 사본에 후보와 기존 이미지를 각각 실행했다. 원본 계정이나 운영 DB에는 테스트 계정을 넣지 않는다.

스테이징은 내부 Docker bridge만 사용하며 호스트·공개 포트는 열지 않는다. 검사기는 해당 서버의 내부 컨테이너 IP로 HTTP·미디어를 읽고, 임시 관리자·Socket.IO 검사기는 격리된 후보 안에서 동작한다. 운영 전환 후보만 기존 운영 네트워크와 loopback 51739를 사용한다.

백업, 비밀 환경 설정, 원본 DB 레코드와 상세 검사 증거는 CI artifact나 Git에 올리지 않는다. 실패 시도의 데이터 사본도 보존하며 임시 컨테이너·네트워크만 소유·격리·이미지 식별을 확인한 후 종료한다.

[사본 검증 41208453549](https://github.com/sebaram/multi_display_artworks/actions/runs/41208453549)이 통과했다. 원본 컬렉션의 BSON digest·개수·참조 순서·index, 원본 이미지·splat·GLTF 바이트, 임시 관리자 로그인, 기본 44 preset의 반복 가져오기, 동영상 업로드·Range 206·적용·재시작 유지, 두 방문자 포인터와 play/pause/seek를 확인했다. 후보가 쓴 사본에 기존 이미지를 실행해 갤러리·미디어를 확인하고 후보로 돌아온 뒤 저장 유지와 임시 데이터 정리도 확인했다. 검증한 제품 소스에 `v2.0.0-rc.1` 태그를 보존했다.

검사 샘플은 기존 MongoEngine과 동일한 `_cls` 조건을 사용한다. 원본의 첫 무조건 조회 이미지 레코드는 기존 Flask에서도 404였으며 수정·삭제하지 않았다. 실제 미디어에 저장된 동일 출처 절대 URL은 경로만 추출해 격리된 사본의 바이트를 비교했다. 외부 미디어 서비스의 현재 가용성을 사본 검사 성공으로 주장하지 않는다.

## 전환 조건

1. 사본에서 원래 ID·참조 순서·계정 hash·index·미디어를 비교한다. 임시 관리자 로그인, preset·업로드·적용·재시작 유지, 두 방문자 반응·재생 상태를 확인한다.
2. 후보가 쓴 사본에 기존 이미지를 다시 실행해 갤러리·미디어 복구를 확인하고 후보로 복귀한다.
3. `2.0.0` 버전과 문서를 정리한 PR을 일반 merge commit으로 `master`에 병합한다. 최종 master SHA의 push CI 성공 후 같은 SHA를 새 이미지로 준비하고 다시 사본 검증한다.
4. 최종 짝지은 백업 후 후보를 비공개 51739에서 확인한다. 기본 44 preset은 기존 항목을 덮어쓰지 않는 가져오기로 추가한다. 같은 이미지만 공개 51736으로 승격한다.
5. 공개 HTTPS·방·월 고유 주소·Socket.IO를 확인한 후 실제 배포 커밋에 `v2.0.0` 태그와 GitHub Release를 기록한다. 실패 시 이 전환에서 캡처한 기존 이미지·설정으로 복구한다.

## 명시적으로 남은 확인 범위

기존 운영 사용자의 실제 비밀번호 로그인은 아직 확인하지 않았다. 계정 hash 보존과 격리 사본의 새 관리자 로그인 검사를 구분한다. 쿠키 전환으로 배포 후 재로그인이 필요하다.

Quest 3 실제 VR/controller/hand 확인, 물리 마이크·카메라·외부망 TURN, 휴대폰 자원·발열 전수 측정은 수행하지 않는다. YouTube의 외부 제공자 차단은 실제 재생 성공으로 취급하지 않는다. 비공개 FLAME/GaussianAvatars 자산은 운영 이미지와 서비스에 포함하지 않는다.
