# MetaMuseum 2.0 출시 검토안

작성: 2026-10-31 (Asia/Seoul). 상태: **사용자 승인 후 실행 중**. 보존 브랜치 이름은 사용자 지시에 따라 정확히 `legacy-flask`로 확정했다. RC 버전과 배포 준비를 진행하며, 운영 전환 완료 여부는 실행 기록으로 구분한다.

## 판단

기존 Flask 구현을 보존하고 새 구현을 `master`에 병합하는 방향을 권장한다. 제품 버전은 `2.0.0`으로 정리하되, 먼저 `2.0.0-rc.1` 후보를 운영 데이터 사본에서 확인한다. 첫 운영 전환은 수동 승인으로 진행하고, 자동 배포 활성화는 이후 별도로 다룬다.

RC 코드 검증과 운영 데이터 사본의 복원·기능·기존 이미지 복구 검증이 통과했다. 정식 버전은 `2.0.0`으로 정리하며, 최종 master SHA의 CI와 새 정식 이미지의 사본 검증·비공개 확인·공개 전환은 별도로 진행한다. 실제 상태와 증거는 [실행 기록](v2.0-execution.md)을 기준으로 한다.

## 기존 버전 보존과 병합

1. 운영 호스트에서 실행 중인 `metamuseum_container`의 이미지 ID와 해당 배포 소스 SHA, Compose/환경 설정의 식별 정보를 확인한다. 비밀값을 Git에 넣지 않는다.
2. 확인한 운영 SHA에 보존 브랜치 `legacy-flask`와 annotated tag `production-pre-v2-20261031`을 만든다. 운영 SHA가 `974bbfd`와 다르면 실제 운영 SHA와 기존 `master` 기준을 둘 다 보존한다. 브랜치는 새 Flask 개발 약속이 아니라 복구 기준이다.
3. 실행 중인 이미지도 변경되지 않는 별도 태그와 ID로 보존하고 필요하면 이미지 아카이브를 만든다. 계속 덮어쓰는 `latest`나 `rollback` 태그 하나만 믿지 않는다.
4. 출시 준비 커밋을 현재 작업 브랜치에 모아 `master` 대상 PR로 검토한다. 82개 커밋을 통째로 squash하기보다 일반 merge commit(`--no-ff`)으로 세대 전환 지점을 남기는 안을 권장한다.
5. 병합 후 코드는 `master`가 정본이다. 기능 브랜치와 보존 브랜치는 첫 배포·롤백 확인 전에는 삭제하지 않는다.

브랜치·태그는 코드 복구용이다. 운영 이미지, 비밀 설정, MongoDB와 미디어 백업을 대신하지 않는다.

## 버전 정책

프레임워크 교체만으로 SemVer major가 강제되는 것은 아니다. [SemVer](https://semver.org/)는 공개 API의 호환성 변경을 기준으로 한다. 이번에는 전체 UI·서버·배포 단위 교체, 세션 쿠키 전환, 일부 Flask-Admin 내부 프로토콜 폐기가 함께 있어 제품의 새 세대를 `2.0.0`으로 표시하는 것이 적절하다.

- 준비/스테이징 후보: `2.0.0-rc.1`. 수정한 후보에는 새 RC 번호와 태그를 사용한다.
- 정식 출시: 검증된 소스 커밋에 `v2.0.0` 태그와 GitHub Release를 만든다. RC 이미지와 정식 이미지의 버전 표기가 다르면 정식 이미지를 새로 빌드·식별한다.
- 확정 후 backend 패키지, frontend 패키지와 lockfile, FastAPI 버전 정보와 생성 OpenAPI 계약을 같은 제품 버전으로 맞춘다. 실행 이미지의 Git SHA/릴리스 버전도 식별 가능하게 한다.
- 기존 `/api/v1` URL, Mongo 스키마 버전, 아바타/벽 프로토콜 버전은 제품 버전과 별개다. `2.0.0`이라는 이유만으로 `api/v2`나 스키마 번호를 일괄 변경하지 않는다.
- 과거에 발행하지 않은 `v1.0.0` 릴리스를 사실처럼 새로 만들지 않는다. Flask 기준은 명시적인 legacy/prod 보존 태그로 기록한다.

## 연구 기능과 검증 범위

- Procedural gaze는 기본 꺼짐의 연구 알고리즘이다. attention 가중치·필터·시선 각도를 다룰 수 있지만 실제 눈 추적, 주의 측정, 상대가 알아채지 못한다는 결과를 주장하지 않는다.
- GaussianAvatars subject 306은 로컬 연구용 머리·상체 모델이다. FLAME/subject 데이터는 저장소·운영 이미지에 포함되지 않고 production asset API와 catalog에서 차단된다. 동적 Gaussian LOD·대규모 인원 성능·전신 지원을 정식 기능으로 광고하지 않는다. [개발 상태](../gaussian-avatar-gaze.md).
- LG V35에서 WebGL, 외형 저장/재로드, 실제 touch 이동과 PC 관찰자 반영을 제한적으로 확인했다. 휴대폰 CPU/GPU/RAM/FPS·열·배터리 전수 측정은 하지 않았다.
- Quest 3 실제 VR/controller/hand 확인은 완료하지 않았다. A-Frame mock XR 검증과 분리한다. XR 지원을 정식 보증하려면 배포 후보에서 짧은 실제 입장·컨트롤러·손·종료 확인이 필요하다.
- 음성 CI는 실제 WebRTC 연결과 합성 마이크를 사용한다. 실제 마이크/카메라, 서로 다른 외부망, TURN은 별도 운영 확인 대상이다.
- YouTube CI는 실제 재생·일시정지·탐색 성공과 명시적인 `LOGIN_REQUIRED` 봇 차단에 대한 오류/원본 링크 검증을 구분한다. 기록된 `external_blocked`는 실제 재생 성공이 아니다. 로컬 실제 YouTube 재생과 앱 HTTP/Socket.IO를 사용하는 제어 플레이어 검사는 별도 증거다.

## 권장 전환 순서

1. 현재 운영의 소스·이미지·설정을 식별하고 보존 브랜치/태그/이미지를 확보한다.
2. 짝지은 운영 백업으로 staging 복원 및 기존 이미지 롤백을 짧게 리허설한다.
3. 배포 제안의 사전 검사·권한·rollback 조건을 수정하고 README/CHANGELOG/버전을 확정한다. 검증된 RC 이미지와 식별 정보를 남긴다.
4. PR을 통해 `master`에 일반 merge하고 병합 결과의 CI를 확인한다. 첫 공개 전환은 자동으로 실행하지 않는다.
5. 이미지 빌드는 쓰기 중단 전에 끝낸다. 전환 시점에 기존 컨테이너 정지 등 확정한 방법으로 HTTP·Socket.IO 쓰기를 함께 멈추고, 최종 일관된 DB/미디어 snapshot 후 확정한 버전의 이미지로 전환한다. 현재 앱에 전용 read-only 모드가 있다는 전제는 두지 않는다. 첫 전환에는 짧은 서비스 중단을 계획한다.
6. 전환 직후에는 외부 쓰기 중단을 유지하고 운영자에게만 health·로그인·대표 room/wall/image/splat/GLTF·두 탭 실시간·preset 업로드/적용·공유 MP4 확인을 허용한다. 이를 위한 운영자 전용 접근 방법도 전환 전에 준비한다. 약속할 XR 범위에는 별도의 실제 기기 확인을 포함한다. 스모크 통과 후 외부 접속/쓰기를 재개하고, 실패하면 제한을 유지한 채 롤백을 결정한다.
7. 성공한 소스·이미지 digest·백업·운영 확인 결과를 릴리스에 기록한다. 초기 안정화 후 master 자동 배포를 별도 활성화할지 결정한다.
