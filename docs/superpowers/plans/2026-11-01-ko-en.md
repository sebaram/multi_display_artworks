# Korean and English UI implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Offer Korean and English throughout the service; keep the README and release documentation English-only.

**Architecture:** A small shared React/external-store locale module provides explicit Korean/English message pairs and interpolation. React components subscribe without remounting scenes or editors; imperative controls subscribe for label updates. Persist the choice locally and keep all API identifiers, user content and stored designs unchanged.

**Tech Stack:** Existing React 19, TypeScript, localStorage, Vitest and Playwright; no new runtime dependency.

**Spec:** User requested Korean and English service UI, then clarified that the README and release documentation should remain English-only. Korean stays the service default; an accessible compact switch offers 한국어 / English. Invalid or unavailable storage falls back safely. HTML language and page title follow the selection.

## Global constraints

- Preserve ongoing drafts, media playback, room connections and permanent URLs when switching language.
- Translate application labels, help, empty states, validation and accessibility text; preserve user-authored names, model/preset identifiers and external-service content.
- Keep one English README.md; release notes, changelog and release records also stay English.
- Follow AGENTS.md: focused tests and a brief desktop/mobile browser smoke; no deployment, full performance matrix or physical XR checks in this task.

## Review focus

- Switching language while an editor has an unsaved draft must retain that draft.
- Imperative room/avatar controls must update without reconnecting or remounting the scene.
- Disabled localStorage and invalid saved values must not block startup or switching.
- Translated labels must not alter admin field keys, enum values, route IDs or submitted user content.
- Long English labels must remain usable in compact mobile navigation and dialogs.

## Shared interface

`frontend/src/app/i18n.ts` exports `Locale = 'ko' | 'en'`, `LOCALE_STORAGE_KEY = 'metamuseum.locale'`, `getLocale()`, `setLocale(locale)`, `subscribeLocale(listener)`, `translate(ko, en, values?)`, and `useI18n()` returning `{ locale, setLocale, t }`. Interpolation uses `{name}` with string/number values. Outside React, use `translate` and subscribe for existing DOM labels. Within React, call `useI18n()` in each component that renders localized copy. `LanguageSwitcher` lives at `frontend/src/app/LanguageSwitcher.tsx`.
