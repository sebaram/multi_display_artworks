최적화 고정 버퍼 실행은 품질 제어기를 level 0에서 끈 조건입니다. 이미지의 화면 크기 LOD, 자산 상주 제어, splat LOD는 계속 적용되므로 기존과 같은 시각 품질을 뜻하지 않습니다. 관측된 렌더 버퍼가 모두 같을 때만 차이를 계산하며, 월 소스 해상도·활성 splat·이미지 LOD의 차이도 옆에 표시합니다. 적응형 결과에는 렌더 해상도와 LOD 조절에 따른 품질 절충이 추가로 포함됩니다.

02

장면별 전후 비교

CPU에는 브라우저 내 관찰 코드와 결과 반환 비용이 포함됩니다. 관찰량이 빌드마다 달라 순수 앱 CPU 가속률로 해석하지 않습니다. 각 실행의 CPU 관찰 구간 길이는 상세에 표시합니다.

입력에 제공된 화면을 이 파일 안에 포함했습니다. 화면을 누르면 확대됩니다. 화면만으로 미세한 품질 차이와 시간에 따른 깜박임을 모두 검증할 수는 없습니다.

05

측정 방법과 해석의 한계

  1. 워밍업 이후 측정. 초기 상주 작품의 준비 확인과 워밍업 이후 구간을 관찰합니다. 회전 중에는 로딩·퇴거·재요청이 이어집니다. 준비·측정 시간, 실행 순서, 반복 수는 입력 원자료에서 확인합니다. 기록이 없는 시간은 임의로 채우지 않습니다.
  2. 정지 시점과 360° yaw 경로. 정지 시점은 가시성·상주 자산의 차이가 크게 드러날 수 있고, 360° 회전은 시야 전환·재상주 비용을 포함합니다. 이동 중 실제 자산 재요청·LOD 전환 비용과 로딩 대기가 포함됩니다. 끝 시점의 미완료 상주 작품 수를 상세에 표시하며, 완전히 같은 렌더 작업량을 뜻하지 않습니다. 두 경로를 합쳐 평균 내지 않습니다. 장면 이름과 실행 상세의 카메라 경로를 확인합니다.
  3. 집계와 FPS 범위. 프로필 + 장면 + 빌드·품질로 묶고 status = ok인 실행만 집계합니다. 각 지표의 유한 숫자만 사용하므로 지표마다 유효 표본 수가 다를 수 있습니다. FPS·CPU·메모리·카운터는 중앙값, p95·p99는 반복 최댓값입니다. FPS는 메인 장면의 렌더 호출 횟수이며 Spark 내부 패스를 따로 세지 않습니다. 새 비교 실행에서는 GPU 타이머를 사용하지 않습니다. 실패 실행과 오류는 상세 원자료에 남깁니다.
  4. CPU. Chrome 전체 프로세스 합계의 코어 사용률이며, 브라우저 안에서 수행한 측정 코드와 측정 결과 반환·직렬화 비용도 포함합니다. 이미지 크기 관찰량이 빌드마다 달라 관찰 오버헤드가 비대칭입니다. FPS의 10초 구간보다 CPU·RAM 관찰 구간이 길 수 있고 그 길이를 상세에 기록했습니다. 순수 앱 렌더링 CPU 절감률로 해석하거나 별도 보정하지 않습니다. 1논리 코어 = 100%이므로 100%를 넘을 수 있습니다. 운영체제 전체 사용률이나 기기별 성능 환산값이 아닙니다. 모바일 4배 제한의 제어 스레드 자체도 Chrome CPU 합계에 들어가므로, 그 수치를 실제 앱의 휴대폰 CPU 요구량으로 해석하지 않습니다.
  5. 메모리. JS 힙은 JavaScript만 포함하고, WS는 Chrome 프로세스의 상주 페이지 합계로 공유 페이지가 중복될 수 있습니다. private commit은 실제 상주 RAM과 다릅니다. GPU 전용 메모리는 앱 프로세스의 스냅샷이며 실행 중 피크가 아닙니다. 반복 후 잔존 메모리 비교는 누수의 존재·부재를 정확히 증명하지 않습니다.
  6. 품질·기능. 같은 렌더 버퍼여도 월 소스 해상도·splat LOD·상주 자산 수는 다를 수 있습니다. 절감량은 실제 버퍼·소스·예산·카운터와 함께 읽습니다. 적응형 해상도·LOD의 시각 품질, 원본 접근, 재생 동기화, 편집·선택, AR/XR 회귀는 검증 항목을 따로 확인합니다.
  7. 기기 범위. 모바일 스트레스는 이 호스트 PC의 제한 조건입니다. 실제 휴대폰·Quest 3의 GPU, RAM, 발열, 배터리, XR 스테레오 성능이나 장시간 안정성으로 환산하지 않습니다.
